# R12 brief: pipeline tooling, hosting a custom fine-tune, privacy tools (as of 2026-11-01)

Research for counsel and engineers, not legal advice. 89 facts in `raw/R12.jsonl`. Licence verdicts are research views. All GitHub star and commit figures come from the GitHub API relayed through a fetch model, so verifier V should recheck them.

## Recommendation: cheapest solid stack

One scheduler, one ephemeral GPU, one trainer, one gate, one registry. Nothing needs Kubernetes or Airflow.

| Step | Pick | Why / fact_ids |
|---|---|---|
| Schedule | Prefect OSS (Apache, 24,103 stars) or plain cron; Prefect Cloud Hobby is free (R12-053, 054) | Dagster and ZenML are also Apache and fine (R12-055, 058); Airflow and Kubeflow are heavier (R12-056, 057) |
| GPU lifecycle | Create, run and terminate a RunPod pod through its API, or SkyPilot managed jobs (R12-050, 051, 052) | SkyPilot tears down when the job ends; RunPod support is community-maintained. Do not stop/start pods: a restart can return zero GPUs (R12-050). Modal cron is the alternative (R12-048, 049) |
| Train | Axolotl (Apache, no exceptions found) or Unsloth core (R12-009, 010, 001, 002) | Both support GPT-OSS and QLoRA. Keep Unsloth's `studio/*` and `unsloth_cli/*` out: they are AGPL-3.0, so Counsel (R12-001) |
| Gate | lm-evaluation-harness (MIT) for general regressions, promptfoo (MIT) or Inspect AI (MIT) for the private brand suite (R12-083, 084, 087) | lm-eval loads PEFT adapters and talks to vLLM. DeepEval is Apache, but never run `deepeval login` on the trainer (R12-085) |
| Registry | Self-hosted MLflow (Apache) with aliases for per-tenant pointers (R12-061, 062) | W&B is now under CoreWeave and its self-hosting is not described (R12-063, 064). Hugging Face private Hub costs 18 USD per TB per month, but is third-party storage (R12-066) |
| Serve | vLLM multi-LoRA (Apache, 96,052 stars) | GPT-OSS MoE LoRA works from vLLM 0.15.0 (R12-031). Smoke-load every new adapter on staging first (R12-033) |

Dropped: torchtune is no longer actively maintained (R12-022). ms-swift is Apache but its README never mentions gpt-oss (R12-026). TRL, LLaMA-Factory, Oumi and NeMo Automodel all list GPT-OSS and are valid alternatives (R12-016 to R12-025).

**GPT-OSS cost of entry.** Memory is 14 GB QLoRA or 44 GB BF16 LoRA for 20b, and 65 GB or 210 GB for 120b (R12-006, 007, 014). The expert weights are MXFP4 and must be dequantised for training (R12-030). The model must always use the harmony format; this is the first thing to check for "less clean" answers than GPT-4, though I found no source linking the two (R12-029). Sharded FSDP saves need a manual `config.json` fix (R12-015).

## Answer: can a fine-tuned model be hosted where Synquic already runs?

- **Groq: not for this model, as documented.** LoRA only, enterprise tier only, and the only listed base is Llama 3.1 8B. gpt-oss is not mentioned. Price is not published, so unverifiable (R12-034, 035).
- **Cerebras: only on Dedicated Inference, enterprise, by contract.** Fine-tuned weights of the same architecture are accepted, and GPT-OSS is a listed family. Price and terms are not published (R12-036). Shared Inference lists only gpt-oss-120b and qwen-3.8-27b and says nothing about custom models (R12-037, unverifiable). Get both in writing for the exact base.
- **Fireworks: documented fit.** Full weights and LoRA uploads accepted, GPT-OSS 120B and 20B named, LoRA on dedicated deployments only, H100 at 8.00 USD per hour (R12-042, 043).
- **Together: documented, gpt-oss upload unconfirmed.** Adapters and fine-tuned weights go to dedicated endpoints; serverless LoRA is discontinued; H100 5.49 USD per GPU-hour (R12-038, 039, 040).
- **Baseten** allows custom models but gpt-oss LoRA is unconfirmed (R12-044, 045). **OpenRouter** shows no custom-model route (R12-046). Hugging Face Endpoints list GPUs from 1.8 USD per hour but say nothing on private models (R12-047).

Net: serving Synquic's own LoRA means a dedicated GPU somewhere, not a per-token API. That fits the credit model only if a base replica is shared across brands.

## Privacy: what it guarantees

1. **Redaction first, but not a guarantee.** Presidio (MIT) says it may miss sensitive data (R12-067, 068). GLiNER PII models: urchade is Apache (R12-070); NVIDIA's is a custom licence and English only, so Counsel (R12-071).
2. **Confidential GPU for the training pod.** Azure NCC H100 v5 is 6.98 USD per hour for one H100 (R12-075, 076). Google A3 High uses Intel TDX with H100 in three zones, with a known GPU-attestation bug that needs a full restart (R12-077). Phala's H200 TEE has a 24-hour minimum (R12-081). I found no evidence RunPod offers confidential GPUs, and its docs rely on a contractual ban on hosts inspecting pods (R12-082).
3. **What confidential computing really gives.** The operator or hypervisor cannot read VM memory, and the workload can be attested (R12-078, 076). It does not protect against guest admins, the tenant host software remains trusted (R12-080), GPU memory is not encrypted on the package (R12-078), and an independent paper calls the design hard to inspect (R12-079). So "no one at Synquic can see brand data" needs a locked image (no SSH, attested, customer-managed keys), not just a confidential SKU.
4. **Leak audit.** I found membership-inference libraries (Fast-MIA, pandora_llm) but no canary-insertion tool (R12-074); build canaries in-house. DP fine-tuning on LoRA costs real utility and has no small-data evidence (R12-072, 073): not recommended as the primary control.

## What would change the answer

- If Cerebras or Groq confirm GPT-OSS or Gemma 4 LoRA hosting in writing at an acceptable price, serve there and drop self-hosted vLLM.
- If the bake-off picks Gemma 4 or Qwen, the framework choice stays; only the GPT-OSS-specific fixes (R12-015, 029, 033) fall away.
- A finding that confidential GPUs are required by enterprise buyers moves training from RunPod (3.99 USD per hour in doc 04) to Azure or Google at roughly 1.7 times the cost per hour (R12-075; my arithmetic).
- Counsel reading AGPL as acceptable would open Unsloth Studio; unlikely to matter for a headless job.
