# R11 brief: GitHub repos and tools to reuse, borrow or avoid

As of 2026-11-01. Facts are in `raw/R11.jsonl` (75 rows). Research, not legal advice. GitHub numbers come from the public GitHub API through a summarising fetch tool; API issue counts include pull requests (R11-004). Several API reads hit a 403 rate limit late in the run; I stopped rather than work around it.

## Recommendation

1. **Reuse no end-to-end repo as a base.** Every project in this space is stock footage plus TTS, single-tenant, or stale. Borrow patterns only.
2. **Rendering: build the core on FFmpeg, buy nothing yet.** Our design (normalise, xfade, zoompan, loudness) is FFmpeg work. Add one optional layer for animated word-level captions: HyperFrames (Apache-2.0) first, Remotion Automators second.
3. **QC: pick licence-clean parts.** PySceneDetect, PaddleOCR, SigLIP 2, a frontier vision LLM, VideoScore2 as a secondary signal. Drop DOVER and FAST-VQA. For identity, trial AuraFace and buy-or-test alternatives; none has AI-video evidence.

## What would change the answer

- Remotion counsel review passing and Synquic being under 4 people: Remotion becomes the simplest captions layer.
- HyperFrames failing a 1080p vertical test: fall back to Remotion or Shotstack.
- Pilot showing AuraFace separation too weak: buy InsightFace or Rekognition.
- A published licence-clean video-quality model with per-clip evidence would replace VideoScore2.
